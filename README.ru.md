# baselinewatch

[English version](README.md)

Синтетический мониторинг веб-приложений по эталонам на базе Playwright.

> **Статус: ранняя разработка.** Устанавливать пока нечего. Здесь описан план
> версии 1.

## Идея

Вы пишете обычные сценарии Playwright и даёте имена шагам, которые важно
измерять. Время каждого шага baselinewatch сравнивает с эталоном, который
утвердил человек, поэтому замеры разных дней и машин можно сравнивать напрямую.
Слишком медленный шаг перед провалом прогона измеряется ещё раз. Каждый прогон
даёт короткий текстовый отчёт, CSV-историю и zip со снимками экрана. Завершается
он кодом возврата, понятным любому планировщику:

| Код | Значение                                                  |
|-----|-----------------------------------------------------------|
| 0   | все шаги в пределах эталона                               |
| 1   | есть медленный или упавший шаг                            |
| 3   | окружение не готово (конфигурация, браузер, блокировка)   |

## План версии 1

- Fixture Playwright для именованных замеров и reporter, который записывает
  результаты.
- Эталоны в отдельном JSON-файле, который проходит ревью, отдельно от настроек
  окружения.
- Командная строка `blw`: `blw init` создаёт проект мониторинга, `blw run`
  выполняет два прохода и строит отчёт.
- Шаблоны для Windows для операторов, которые сами не работают с Node:
  `install.bat` ставит портативные Node и браузер, `monitor.bat` запускает
  мониторинг и возвращает код.
- Вымышленный демо-портал, работает офлайн, служит примером и стендом CI.

Вне рамок: графики, ярлыки, расписание, оповещения.

## Разработка

Репозиторий публичный, и защита от утечек — часть проекта. Перед первым push
включите хук pre-push:

```sh
git config core.hooksPath .githooks
node --test "test/hook/*.test.mjs"
```

Как связаны хук, маркер в pull request и проверки CI, описано в
[docs/public-hygiene.md](docs/public-hygiene.md) (на английском).
